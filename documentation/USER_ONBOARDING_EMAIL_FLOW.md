# User Onboarding Email Flow

**Last Updated**: September 3, 2025

## Overview

This document describes the email flow for new user registration and onboarding in Memverse. The flow has been optimized to reduce email volume and prevent Gmail rate limiting issues.

## Current Email Flow (As of September 3, 2025)

### 1. User Registration
When a new user signs up:
- User fills out registration form
- Account is created in the database with `confirmed_at = nil`
- **Devise Confirmation Email** is sent automatically
- ~~Signup notification email~~ (DEPRECATED - removed to reduce email volume)

### 2. Email Confirmation
When user clicks the confirmation link:
- Devise marks the account as confirmed (`confirmed_at` is set)
- User's account status changes from unconfirmed to active
- `after_update` callback triggers `send_activation_notification`

### 3. Activation Email
The activation email is sent after successful confirmation and includes:
- Welcome message
- Login email reminder
- Getting started recommendations:
  - Complete profile
  - Set email preferences
  - Add first verses
- Links to key features
- Help and contact information

## Email Templates

### Active Templates
- **Devise Confirmation Email**: System-generated by Devise
  - Template: Devise default (customizable in `app/views/devise/mailer/`)
  - Purpose: Email address verification
  
- **Activation Email**: Sent after confirmation
  - Templates: 
    - HTML: `app/views/user_mailer/activation.html.erb`
    - Text: `app/views/user_mailer/activation.text.erb`
  - Purpose: Welcome user and provide onboarding guidance
  - Postmark Stream: `outbound`
  - Postmark Tag: `account-activation`

### Deprecated Templates
- **Signup Notification Email** (DEPRECATED as of Sep 3, 2025)
  - Templates: 
    - `app/views/user_mailer/signup_notification.html.erb` (kept for reference)
    - `app/views/user_mailer/signup_notification.text.erb` (kept for reference)
  - Reason for deprecation: Redundant with confirmation email, caused Gmail rate limiting
  - Content merged into: Activation email

## Benefits of Current Flow

1. **Reduced Email Volume**: From 3 emails to 2 emails per signup (33% reduction)
2. **Better Email Spacing**: Natural delay between confirmation and activation
3. **Improved Deliverability**: Less likely to trigger Gmail rate limits
4. **Consolidated Content**: All onboarding information in one comprehensive email

## Gmail Rate Limiting Prevention

The previous flow triggered Gmail's rate limiting (450 4.2.1 SMTP error) because:
- 3 emails were sent in rapid succession
- Multiple users from same domain (e.g., @gmail.com) signing up simultaneously
- No delay between emails

The new flow prevents this by:
- Reducing total email count
- Natural spacing between emails (user action required)
- Consolidating welcome content into activation email

## Migration Notes

### For Developers
- The `send_signup_notification` callback has been removed from User model
- The signup_notification email templates are retained for reference but not used
- All welcome content has been merged into the activation email
- Tests have been updated to reflect the new flow

### For Email Analytics
- "signup-notification" Postmark tag will no longer appear in new data
- All onboarding metrics should now track "account-activation" tag
- Historical data for signup-notification remains valid for past users
