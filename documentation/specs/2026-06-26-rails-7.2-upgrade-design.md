# Rails 7.1 → 7.2 Upgrade — Design Spec

**Date:** 2026-06-26
**Status:** Approved (pending spec review)
**Author:** Andy Vitus + Claude

## Motivation

Nine Dependabot security alerts against Rails components (Active Storage, Active
Support, Action View) remain open and **cannot be fixed within the Rails 7.1
line**. Every advisory is patched only at `7.2.3.1` / `8.0.4.1` / `8.1.2.1`; there
is no 7.1.x patched range, because the 7.1 series is past its security-maintenance
window (Rails patches the current series plus the one before — currently 8.0/8.1
and 7.2). The newest 7.1 release (7.1.6) is still flagged.

Therefore the minimum action that clears these alerts is upgrading off 7.1 to
**Rails 7.2.3.1**.

### Alerts this clears (9 — 1 high, 6 medium, 2 low)

| Severity | Component | Advisory |
|----------|-----------|----------|
| high   | activestorage | Path Traversal in DiskService (GHSA-9xrj-h377-fr87) |
| medium | activestorage | DoS in proxy mode via Range requests (GHSA-r46p-8f7g-vvvg) |
| medium | activestorage | Glob injection in DiskService (GHSA-73f9-jhhh-hr5m) |
| medium | activestorage | Content-type bypass via metadata in direct uploads (GHSA-qcfx-2mfw-w4cg) |
| medium | activesupport | DoS in number helpers (GHSA-2j26-frm8-cmj9) |
| medium | activesupport | XSS in SafeBuffer#% (GHSA-89vf-4333-qx8v) |
| medium | activesupport | ReDoS in number_to_delimited (GHSA-cg4j-q9v8-6v38) |
| low    | activestorage | DoS in proxy mode via multi-range requests (GHSA-p9fm-f462-ggrg) |
| low    | actionview | XSS in Action View tag helpers (GHSA-v55j-83pf-r9cq) |

## Goal

Move the app to **Rails 7.2.3.1** with **`config.load_defaults 7.2`**, clearing all
9 alerts, while maintaining 100% passing tests (RSpec, Vitest, Cucumber).

## Non-Goals

- Rails 8.0 (bigger jump; would require acts-as-taggable-on 12; not needed to clear alerts).
- The non-Rails alerts: addressable (blocked by onebox `~> 2.8.0`), devise, bcrypt,
  sidekiq-cron, rexml — tracked separately.
- Production deployment (handled via existing Capistrano/Passenger flow afterward).

## Current State

- Rails **7.1.5.2**, Ruby **3.2.6** (satisfies Rails 7.2's `>= 3.1`).
- `config/application.rb`: `config.load_defaults 7.1`.
- Existing `new_framework_defaults_6_0/6_1/7_1.rb`; **no 7.2 file yet**.
- `Rails.application.secrets` already removed (recent "Consolidate to Rails 7
  credentials" commit) — pre-clears a 7.2 blocker, since 7.2 removes `secrets`.

## Dependency Changes (resolution blockers)

| Gem | From | To | Why |
|-----|------|----|----|
| rails | `~> 7.1.0` | `~> 7.2.0` | direct pin caps at 7.1.x |
| acts-as-taggable-on | `~> 10.0` | `~> 11.0` | 10.0 requires `activerecord < 7.2`; 11.0 = `>= 7.0, < 8.0` |

Other engines already permit 7.2 and need no change: thredded (`rails >= 7.0`),
rails_admin (`rails < 9`), cucumber-rails (`railties < 9`), ckeditor (uncapped).

Command: `bundle update rails acts-as-taggable-on` (cascades all Rails components
to 7.2.3.1).

## Framework Defaults (`load_defaults 7.2`)

1. `bin/rails app:update` to generate `config/initializers/new_framework_defaults_7_2.rb`
   and surface diffs to `config/` and `bin/`. Reconcile changes **without clobbering**
   project customizations (review each proposed change).
2. Flip `config/application.rb`: `config.load_defaults 7.1` → `7.2`.
3. Review each new 7.2 default and enable deliberately. Notable: YJIT enabled by
   default (Ruby 3.2 supports it). MySQL is the DB, so Postgres-specific defaults are
   N/A. Anything risky can be left explicitly at the 7.1 value in the new_framework
   defaults file and adopted later.

## Code / Deprecation Work

- Resolve any 7.1→7.2 deprecation warnings (test env raises on *disallowed*
  deprecations; `config.active_support.deprecation = :stderr`).
- **acts-as-taggable-on 10 → 11:** review changelog for breaking changes and any new
  migration; run `db:migrate` if it ships one. Tagging is a core feature used by
  Verse, Memverse, User models, TagController / VersesController / UtilsController /
  MemversesController, the RefreshTagCloud worker, and a rake task — so it receives
  dedicated regression focus.

## Testing & Verification

- Run suites **serially** (RSpec and Cucumber share the MySQL test DB; concurrent
  runs cause non-deterministic failures). Vitest may run alongside either.
- Definition of done:
  - RSpec 1227 examples / 0 failures / 25 pending
  - Vitest 409 passed
  - Cucumber 72 scenarios / 559 steps passed
  - After push, all 9 Rails Dependabot alerts auto-close (open drops 15 → 6:
    addressable, devise ×2, bcrypt, sidekiq-cron, rexml).

## Sequencing (commits)

- **Commit A** — Dependency bump: `Gemfile` + `Gemfile.lock` (rails `~> 7.2.0`,
  acts-as-taggable-on `~> 11.0`) plus the minimal code/deprecation fixes needed to get
  green while still on `load_defaults 7.1`.
- **Commit B** — Defaults adoption: `config.load_defaults 7.2` +
  `new_framework_defaults_7_2.rb` + `bin/rails app:update` reconciliation + any
  resulting fixes.

Keeping the gem bump separate from the defaults adoption makes a regression
bisectable.

## Risks

- **acts-as-taggable-on major bump** touching a core feature — mitigated by the
  existing tagging test coverage and a dedicated regression pass.
- **7.2 default behavior changes** — mitigated by reviewing each in the
  new_framework_defaults file and the full serial suite; risky ones can stay at the
  7.1 value initially.
- **Engine runtime compat on 7.2** (Thredded, RailsAdmin, CKEditor) — dependency
  constraints allow 7.2; runtime behavior is covered by RSpec/Cucumber (e.g. forum
  voting scenarios).
